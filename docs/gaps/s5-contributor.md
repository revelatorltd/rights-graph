# S5 Contributor portal — gaps

`src/surfaces/contributor/`. Sureel's portal for one peer contributor's walled-off tenant. The
tenant is **Meridian Music Group** (`p-meridian`, an invented stand-in for a peer major), and the
signed-in user is Dana Whitfield, the contributor admin. Every page was opened at 1440×900 and the
F4 flow was clicked through end to end. Pages were **not** checked at phone width.

## Decided here rather than asked

- **Addresses**: `#/contributor/<page>/<id>/<facet>`, with pages `overview`, `coverage`, `batches[/<id>[/row-errors|match-results]]`, `upload[/<batchId>]` (a cover; with an id it resubmits that batch and opens at the schema check), `mapping`, `matches`, `conflicts[/<id>[/share-totals]]`, `sharing`, `access`, `charter`, `audits`, `keys`.
- **Nav**: five destinations: Overview (Overview, Coverage), Uploads (Batches, Field mapping), Matching (Match results, Conflicts), Privacy (Sharing, Access log), Governance (Charter, Audit reports, Signing keys).
- **Nothing is ingested before the check passes**: `receive()` holds a CSV with 1.68% failing rows at `batch:Row errors`. Ingesting is reachable only by fixing (resubmitting a corrected file over the same batch) or dropping the failed rows. **Drop failed rows and ingest** is a `ConfirmationDialog` on the batch.
- **All batch writes go through the graph's setters** (`addBatch`, `setBatchState`, `updateConflict`). The portal's own state (row errors per batch, the mapping, sharing, the access log, the tenant's coverage, match samples, its own claims) is in `data.ts` and redraws through `wrote()`.
- **An ingest is read**: matching a batch adds a `Resolver v1.3` read of shared fields to the access log, and moves coverage, read against that upload (F4-5).
- **A conflict that holds no claim of the tenant's** (e.g. `#/contributor/conflicts/cf-1`) is the permission-denied state ("Not a conflict on your claims"), not "not found". An unknown batch says it is "only ever its contributor's".
- **Access-log fixtures**: I added reads the graph's tenant does not hold: a WMG Splits API read (shared fields only, to show that WMG reads like anyone else), a second audit read, a PRS read and an older resolver run. Audit reads touch **Private** fields only. An Encrypted field is described as unreadable by Sureel, so no read of one is logged.
- **Field mapping**: confirming is a selection command (Gmail-style). Confirm is unavailable when an unmatched header is held. Mapping one header by hand is a `FormDialog` whose choice *is* the target field library (`TARGET_FIELDS`, searchable). An unmapped header is never ingested.
- **Governance**: the Charter is a `DetailPage` on the charter document (its promises as facts). Audit reports and Signing keys are `CollectionPage`s. A key row links to the verification portal (`#/verify`).
